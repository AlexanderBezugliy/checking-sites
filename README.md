# CHECKINGS-Sites — что умеет бот

Telegram-бот `@checkingsites111_bot` следит за списком сайтов из `sites.json` и пишет в группу **MONITOR**.

Проверка запускается:

- **аптайм** автоматически **два раза в день** — 09:00 и 21:00 по Киеву;
- **индексация Google** автоматически **раз в сутки** — 10:00 по Киеву;
- вручную кнопкой **«Проверить статус сейчас»** (только аптайм);
- вручную из GitHub: Actions → Periodic Site Monitor / Daily Index Monitor → Run workflow.

Сайт считается **живым**, если есть DNS (NS + IP) и ответ **HTTP 200** или **503** (клоака — это норма, не авария).

HTTP-проверку бот всегда делает с `/?view=d7Fm2Kp9Qx4Nw8Rz` (обход клоаки), как при ручной проверке. В `sites.json` и в отчёте URL остаётся без этого параметра.

## Что бот проверяет

| Проверка | Что считается проблемой | Алерт |
| --- | --- | --- |
| DNS / NS | Нет NS, домен не резолвится, SERVFAIL | Да |
| Сайт открывается | HTTP 200 | Нет (ок) |
| Клоака | HTTP 503 | Нет (норма) |
| SSL уже мёртв | Ошибка сертификата / TLS | Да |
| SSL скоро | До конца сертификата **≤ 7 дней** | Да (один раз, когда попал в окно) |
| HTTP-ошибки | 403, 404, 500, 502, 504 и др. | Да |
| Смена NS | Набор NS изменился с прошлой проверки | Да |
| Эталон NS | Живые NS не совпадают с `ns` в `sites.json` | Да (только при переходе) |
| Чужой редирект | 301/302 на **другой** домен | Да |
| Индексация Google | Главная / внутренние URL выпали из индекса | Да (отдельный daily job) |

`www` и без `www` одного и того же имени чужим редиректом не считаются. Редирект на том же домене (другой путь) — норма.

## Когда пишет в Telegram

- **Сайт упал** или **ожил**.
- **Сменились NS** (с прошлой проверки).
- **Эталон NS не совпал** или **снова совпал**.
- **Редирект на чужой домен**.
- **SSL истекает за 7 дней**.
- **Страница выпала или попала в индекс Google** (отдельный отчёт раз в сутки).
- Если ничего не поменялось — по расписанию **тишина**.
- «Всё тихо» (сводка: сколько живых, сколько 200 / 503, топ медленных) — не чаще **двух раз за 24 часа**.
- Кнопка **«Проверить статус сейчас»** всегда присылает сводку, даже если изменений нет.

Сообщения уходят в группу MONITOR. Личка с ботом отчёты больше не получает.

## Чего бот не делает

- Не считает посещения / трафик (клики из GSC можно добавить отдельно).
- Кнопка **«Проверить статус сейчас»** запускает только аптайм, не индексацию.

## Индексация Google

Отдельный workflow **Daily Index Monitor**. Аптайм и кнопка в Telegram его не запускают.

Список сайтов — только `sites.json` (то, что уже мониторили). `sites.csv` нужен лишь как справочник: колонка `account` (какая Gmail) и `pages` (какие URL). Домены, которые есть только в CSV, **не** проверяются.

Что проверяется:

- **главная** `https://домен/` — каждый день (~433 сайтов);
- внутренние из `pages` (`/login`, `/register`, `/bonus`…) — по очереди, полный круг **~2 дня**;
- слот с минусом (`-bonus`) пропускается;
- нет строки в CSV / нет `account` — skip (сейчас 7 сайтов вроде airnaturel).

Клоака **503** на индексацию не влияет: мы не ходим на сайт с `?view=…`, а спрашиваем Google. Если Google видит 503 и не индексирует — в отчёте будет «не в индексе». Это правда индекса, не падение аптайма.

Секреты GitHub **уже лежат** в Settings → Secrets and variables → Actions:

| Secret | Зачем |
| --- | --- |
| `GSC_CLIENT_SECRET_JSON` | OAuth `web` client |
| `GSC_ACCOUNTS_JSON` | 10 Gmail → refresh token |
| `TELEGRAM_BOT_TOKEN` | аптайм и SEO-алерты |
| `TELEGRAM_CHAT_ID` | группа MONITOR |

В git их нет (локальный `.env` в `.gitignore`).

После пуша кода: Actions → **Daily Index Monitor** → Run workflow. В логе шага сразу будет `SEO start`, затем `SEO progress` каждые 10 URL. Первый прогон обычно **10–20 минут** (4 запроса параллельно, таймаут 15с). В Telegram придёт «база записана». Дальше — только дифф: выпало / попало в индекс.

В `status.json` у каждой строки поле `index`: `indexed` — главная, `pages[]` — все проверенные URL. Аптайм это поле копирует и не затирает. Дашборд может рисовать ОК / не в индексе по `index.indexed`.

## Эталон NS

У сайта в `sites.json` может быть поле `ns` — ожидаемые nameserver-хосты (NS1 и NS2):

```json
{ "url": "https://example.com", "ns": ["ns1.example.net", "ns2.example.net"] }
```

Как править:

- Имена в **lowercase**, без точки на конце, без пробелов. Порядок NS не важен — бот сравнивает как множество.
- Если эталона нет — оставьте только `{ "url": "https://..." }`. Сверки не будет.
- Не сравниваем TLD домена (`.com` / `.gb.net`), только хосты NS.

Что значит результат:

| `ns_match` | Смысл | Telegram |
| --- | --- | --- |
| `true` | ОК — живая зона совпадает с эталоном | Молчим; если раньше было несовпадение — «NS снова совпадают с эталоном» |
| `false` | Эталон есть, а живые NS другие **или** DNS не резолвится | Алерт только когда сверка **стала** неуспешной |
| `null` | Эталона нет, сверки нет | Не пишем |

Поля пишутся в **каждую** строку `status.json` (`ns_expected` и `ns_match`), в том числе при `DNS_ERROR` / `ERROR` / `SSL_ERROR`. Живые `dns.ns` / `dns.a` / `dns.ok` не трогаем.

Дашборд читает только `status.json` с GitHub raw. Рядом с NS-зоной он может показать **ОК** / **не совпало** по `ns_match`. Историю Telegram дашборд не читает.

Сравнение с **прошлой** проверкой («сменились NS») работает отдельно от эталона.

## Как пользоваться

1. Сидеть в группе **MONITOR** (вы и коллега).
2. Смотреть алерты; кнопка в сообщении запускает внеочередную проверку (~30–60 сек).
3. Добавлять и убирать сайты — правкой `sites.json` в репозитории.
4. Логи аптайма: GitHub → Actions → Periodic Site Monitor → **Run monitoring script**.
5. Логи индексации: GitHub → Actions → Daily Index Monitor → **Run index inspection**. Ищите строку `SEO: homes=…`. Без секретов GSC job тихо пишет `GSC не настроен` и аптайм не ломает.

## Если сообщения пропали

Частая причина: группа стала супергруппой, id сменился. В логе будет
`group chat was upgraded to a supergroup chat` и новый `migrate_to_chat_id`.
Его нужно прописать в секрет GitHub `TELEGRAM_CHAT_ID` (токен бота не трогать).
